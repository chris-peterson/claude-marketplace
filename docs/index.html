Claude Code plugins · chris-peterson

bridge.ai

Tools for navigating uncharted waters.

Claude writes code faster than you can track. These plugins keep you in charge: block unsafe commands, review the code as it changes and redirect with in-context feedback, land what you approve as clean commits and change requests, and track your parallel efforts.

Install

Register the marketplace once. After that, install any plugin with claude plugin install <name>@chris-peterson — each one below carries its exact command and a link to full docs.

one-time setup
claude plugin marketplace add chris-peterson/claude-marketplace

Pick your plugins

These are Claude Code plugins; several also ship as standalone CLIs, true to the Unix philosophy. They work together, but every link is soft: start at the top, then add whatever solves a problem you've hit, in any order. The bridge is where a ship is steered from; these are its instruments.

ClaudeWatch

If you find yourself rubber-stamping Claude's approval prompts without really reading them, here's why: its built-in permission model is fundamentally broken — a block on git push --force sails right past git push -f — so it asks about everything to stay safe, and the constant approvals wear you down into decision fatigue. ClaudeWatch makes the checks actually match what they mean: dangerous commands get blocked, and you stop re-approving the same safe one. Install this first.

anchor

When you're nervous about keeping code you didn't write: it walks you through the diff (the exact lines Claude changed) first, then commits with a message about why and opens the change request. Uses whatever diff viewer git already opens for you.

tack

Add it when you keep losing your place between sessions — it remembers what you were doing so you don't re-explain it every time.

logbook

Add it when you've solved something the hard way and don't want to solve it again — it writes up what you learned and shares it with your team.

sextant

Add it when you want requirements captured in source control, kept in sync with the code — either direction — so the spec, not the chat, is the source of truth.

moor

Add it for more integrated code review — step through the AI's changes and send rejections straight back to Claude as a feedback loop. Or skip it; anchor works with whatever diff viewer git already opens.

beacon

Add it when you've got several Claude windows going at once — each shows at a glance whether Claude is working or waiting on you.
