Claude Code plugins · chris-peterson

bridge.ai

Tools for navigating uncharted waters.

Claude writes code faster than you can track. These plugins keep you in charge: block unsafe commands, review the code as it changes and redirect with in-context feedback, land what you approve as clean commits and change requests, and track your parallel efforts.

Install

Register the marketplace once. After that, install any plugin with claude plugin install <name>@chris-peterson — each one below carries its exact command and a link to full docs.

one-time setup
claude plugin marketplace add chris-peterson/claude-marketplace

Pick your plugins

These are Claude Code plugins; several also ship as standalone CLIs, true to the Unix philosophy. They work together, but every link is soft: start at the top, then add whatever solves a problem you've hit, in any order. The bridge is where a ship is steered from; these are its instruments.

ClaudeWatch

If you find yourself rubber-stamping Claude's approval prompts without really reading them, here's why: its built-in permission model is fundamentally broken — a block on git push --force sails right past git push -f — so it asks about everything to stay safe, and the constant approvals wear you down into decision fatigue. ClaudeWatch makes the checks actually match what they mean: dangerous commands get blocked, and you stop re-approving the same safe one. Install this first.

anchor

When you're nervous about keeping code you didn't write: it walks you through the diff (the exact lines Claude changed) first, then commits with a message about why and opens the change request. Uses whatever diff viewer git already opens for you.

tack

Add it when you keep losing your place between sessions — it remembers what you were doing so you don't re-explain it every time.

logbook

Add it when you've solved something the hard way and don't want to solve it again — it writes up what you learned and shares it with your team.

sextant

Add it when you want requirements captured in source control, kept in sync with the code — either direction — so the spec, not the chat, is the source of truth.

moor

Add it for more integrated code review — step through the AI's changes and send rejections straight back to Claude as a feedback loop. Or skip it; anchor works with whatever diff viewer git already opens.

beacon

Add it when you've got several Claude windows going at once — each shows at a glance whether Claude is working or waiting on you.

The instruments

What each one does, grouped by the job it handles.

Stay safeDon't let a bad command through— a check that runs before every shell command

ClaudeWatch

Checks every shell command before it runs. Blocks the genuinely dangerous ones (like git push -f) and asks first before anything that changes your files or project. Catches the tricks simple text-matching misses — commands chained together, flags written in a different order, and other ways a risky command can hide.

tack

cli

To tack is to change course. tack remembers every course you've held.

Keeps track of what you're working on — even across crashes, context overflow, or jumping between projects. Start a fresh session and pick up right where you left off, instead of re-explaining everything.

/tack

beacon

cli

A lighthouse you can read from across the harbor.

Puts a colored badge on each terminal window so you can tell what every Claude session is doing at a glance: green = idle, amber = working, red = waiting on you. Look away and still know which window needs you.

/beacon
Dock safelyBring reviewed work into the record— from dev commits to change requests delivered to main

anchor

An anchor holds a boat in place. This holds your work in place.

Keeps your commits, change requests, and review cycles consistent — the same quality, formatting, and content every time. It walks you through the diff first (keep it, or send back notes and it fixes them), then commits with a message about why and opens the change request, updated to sit on top of the latest main first. Uses whatever diff viewer git already opens.

/preview/commit→/prepare-review/address-feedback

moor

cli

To moor is to tie up alongside and look the hull over.

A fast diff viewer for reading code the AI wrote — step through it one change at a time, accept or reject each with a note. anchor already opens whatever diff viewer git is set to use; moor is just a quick one built for this, and it feeds your notes back to Claude in context.

/moor
Build it rightWork to a plan, keep what you learn— spec-checking and session write-ups

sextant

Fixes your position against a fixed reference — your spec.

Keeps a plain-language spec — what the code must do — in source control alongside the code, and syncs the two in either direction (code→spec or spec→code), flagging whatever has drifted. The spec holds the knowledge, so an implementation can (in theory) be regenerated from it.

/spec-[req|sync|status]/impl-[new|select]

logbook

cli

The ship's log — what the last crew figured out.

After a session, helps you write up what you learned and saves it to a shared team repository. Your chat transcript stays on your own machine — only the write-up gets shared, so the next person inherits the lesson, not just the code.

Example usage

Once you've added them all, here's how a session flows — each step one plugin doing its job, and you still making every call. You won't have all of these on day one, and that's fine.

An always-running safety net — ClaudeWatch

It's already watching before the first command runs — nothing to type. Dangerous commands get stopped; risky ones ask you first.

Where was I? — tack

You open a session. tack reminds you what you were doing and where you stopped — no scrolling back through old chats.

›/tack

Stay on course across windows — beacon

Your window badge turns amber while Claude works and red when it needs you — so you can run several streams at once and still tell which one needs you.

Read the diff — anchor (+ moor, or your own diff viewer)

Claude hands you a diff. You read it — keep what works, send the rest back with a note, and it fixes them.

›/anchor:preview

Commit, then deliver to main — anchor

What passed gets committed with a clear message and opened as a draft change request on its way to main, set to tidy up after itself once merged.

›/anchor:commit

Write down what you learned — logbook

Before you close out, jot the lesson and push it to the team repo — so the next person gets it too.

›/logbook:retro
